PART 1 : WHAT IS IT? (SHORT DEFINITIONS)
--------------------------------------------------------------------------------

Apache / HTTPD
  Apache is a web server program. It receives requests from browsers and sends
  back web pages. On Ubuntu the package is "apache2"; on Red Hat it is "httpd".

HTML / CSS / JavaScript / jQuery
  HTML builds the page structure. CSS styles it. JavaScript makes it interactive.
  jQuery is a JavaScript library that makes things like AJAX shorter to write.

PHP
  A server-side language. Apache runs the PHP code and sends only the result
  to the browser. PHP talks to MySQL.

MySQL
  A database server. It stores data in tables and is queried with SQL.

SMTP
  Simple Mail Transfer Protocol. The protocol used to SEND mail (port 25/587).

Postfix
  A Mail Transfer Agent (MTA). It sends and receives mail using SMTP.

Dovecot
  A mail delivery/reading server. It lets users read their mailbox using
  IMAP (port 143/993) or POP3 (port 110/995).

IMAP / POP3
  IMAP keeps mail on the server and syncs it. POP3 downloads mail to one device.

Cryptography
  Protecting data using mathematics: encryption (hide data), hashing
  (check data has not changed), and digital signatures (prove who sent it).

SSL / TLS
  Protocols that encrypt traffic between client and server. TLS is the newer
  version of SSL. HTTPS = HTTP + TLS. A certificate proves the server identity.

SSH
  Secure Shell. Encrypted remote login to a Linux server (port 22).
  SSH keys are safer than passwords.

Firewall (UFW / iptables / firewalld)
  A filter that allows or blocks network traffic by port, protocol and address.
  iptables is the kernel firewall tool. UFW is an easy front end on Ubuntu.
  firewalld is the front end on Red Hat/CentOS.

ACL (Access Control List)
  A finer permission list. Normal Linux permissions give only owner, group,
  and others. ACLs let you give rights to extra specific users or groups.
  Apache also has ACLs (Require ip ...) to limit who can open a URL.

Anti-spam
  Rules and tools that reject unwanted or fake mail (for example HELO checks,
  sender checks, blocklists, SpamAssassin).

Step 3.14  submit.php  (PHP saves to MySQL and sends a mail notice)
    cat > /var/www/office/submit.php <<'EOF'
    <?php
    require '/var/www/config/db.php';
    header('Content-Type: application/json');

    $name  = trim($_POST['name']    ?? '');
    $email = trim($_POST['email']   ?? '');
    $msg   = trim($_POST['message'] ?? '');

    if ($name === '' || $msg === '' || !filter_var($email, FILTER_VALIDATE_EMAIL)) {
        http_response_code(400);
        echo json_encode(['ok' => false]);
        exit;
    }

    $stmt = $db->prepare('INSERT INTO messages (name, email, message) VALUES (?, ?, ?)');
    $stmt->bind_param('sss', $name, $email, $msg);
    $stmt->execute();

    // Mail notice to IT staff (works after Part 5 is done)
    $subject = 'New helpdesk message from ' . preg_replace('/[\r\n]+/', ' ', $name);
    @mail('bob@office.local', $subject, $msg, 'From: webform@office.local');

    echo json_encode(['ok' => true]);
    EOF

    NOTE: prepare() + bind_param() is a "prepared statement". It protects the
          database from SQL injection.

PART 4 : EMAIL SERVER - POSTFIX + DOVECOT (5.1)

Step 4.1  Create mail users (each gets a Linux account and a mailbox)
    useradd -m -s /bin/bash alice
    useradd -m -s /bin/bash bob
    echo 'alice:Alice@12345' | chpasswd
    echo 'bob:Bob@12345'     | chpasswd




Step 4.2  Install Postfix and Dovecot without prompts
    export DEBIAN_FRONTEND=noninteractive
    debconf-set-selections <<< "postfix postfix/mailname string office.local"
    debconf-set-selections <<< "postfix postfix/main_mailer_type string 'Internet Site'"
    apt install -y postfix mailutils dovecot-core dovecot-imapd dovecot-pop3d




Step 4.3  Configure Postfix (SMTP server)
    postconf -e "myhostname = mail.office.local"
    postconf -e "mydomain = office.local"
    postconf -e "myorigin = \$mydomain"
    postconf -e "inet_interfaces = all"
    postconf -e "mydestination = \$myhostname, localhost.\$mydomain, localhost, \$mydomain"
    postconf -e "mynetworks = 127.0.0.0/8"
    postconf -e "home_mailbox = Maildir/"
    postconf -e "disable_vrfy_command = yes"
    systemctl restart postfix

    Meaning of key settings:
      myorigin / mydestination : which domains this server accepts mail for
      mynetworks               : who may relay mail (only localhost here)
      home_mailbox = Maildir/  : mail is saved in ~/Maildir (Dovecot reads it)




Step 4.4  Configure Dovecot (IMAP/POP3 server)
    cat > /etc/dovecot/conf.d/99-office.conf <<'EOF'
    mail_location = maildir:~/Maildir
    disable_plaintext_auth = yes
    auth_mechanisms = plain login
    EOF
    systemctl restart dovecot

    (Files that load later override earlier ones, so 99- is a safe place.)




Step 4.5  Send a test mail and check delivery
    echo "Hello Bob, server test." | mail -s "Test 1" bob@office.local
    sleep 3
    ls /home/bob/Maildir/new/
    cat /home/bob/Maildir/new/* | head -n 20

    If you see a file in "new", Postfix delivered the mail to Bob.




Step 4.6  Read the mail through Dovecot (IMAP test)
    doveadm auth test bob 'Bob@12345'
    printf 'a1 LOGIN bob Bob@12345\r\na2 SELECT INBOX\r\na3 LOGOUT\r\n' | nc -q 2 localhost 143

    Expected: "auth succeeded" and "a2 OK ... Select completed".




Step 4.7  Check the mail logs

    tail -n 15 /var/log/mail.log        (if the file exists)

4A. ANTI-SPAM MEASURES (Postfix rules)
--------------------------------------------------------------------

Step 4.8  Add basic anti-spam checks
    postconf -e "smtpd_helo_required = yes"
    postconf -e "smtpd_helo_restrictions = permit_mynetworks, reject_invalid_helo_hostname, reject_non_fqdn_helo_hostname"
    postconf -e "smtpd_sender_restrictions = permit_mynetworks, reject_non_fqdn_sender"
    postconf -e "smtpd_recipient_restrictions = permit_mynetworks, reject_unauth_destination, reject_non_fqdn_recipient"
    postconf -e "smtpd_relay_restrictions = permit_mynetworks, reject_unauth_destination"
    postconf -e "smtpd_client_connection_count_limit = 10"
    postconf -e "message_size_limit = 10485760"
    systemctl reload postfix

    What they do:
      helo_required            : sender must say HELO (bots often skip it)
      reject_non_fqdn_*        : reject fake or incomplete addresses
      reject_unauth_destination: server is NOT an open relay
      connection_count_limit   : slows down flooding from one client
      message_size_limit       : max mail size 10 MB




Step 4.9  Optional extra anti-spam (needs internet DNS, may not work in lab)
    - Blocklist check: add  reject_rbl_client zen.spamhaus.org
      inside smtpd_recipient_restrictions.
    - Content filter: apt install -y spamassassin spamc
    - Brute-force protection: apt install -y fail2ban




Step 4.10 Prove it is not an open relay (must be refused from outside)
    From any other machine you would test:  telnet SERVER-IP 25
        MAIL FROM:<x@example.com>
        RCPT TO:<someone@gmail.com>
    Expected: "Relay access denied".

PART 5 : SSL / TLS CERTIFICATE (5.3 CRYPTOGRAPHY)
--------------------------------------------------------------------------------

A real office uses a certificate from a CA such as Let's Encrypt. In a lab with
no public domain we create a SELF-SIGNED certificate. The encryption is the
same. Browsers only show a warning because no known CA signed it.

Step 5.1  Create the private key and certificate (valid 365 days)
    mkdir -p /etc/ssl/office
    openssl req -x509 -nodes -newkey rsa:2048 -days 365 \
      -keyout /etc/ssl/office/office.key \
      -out    /etc/ssl/office/office.crt \
      -subj "/C=NP/ST=Lumbini/L=Butwal/O=Himalaya Trading/CN=office.local" \
      -addext "subjectAltName=DNS:office.local,DNS:mail.office.local"
    chmod 600 /etc/ssl/office/office.key
    chmod 644 /etc/ssl/office/office.crt

Step 5.2  Read the certificate
    openssl x509 -in /etc/ssl/office/office.crt -noout -subject -dates -issuer

--------------------------------------------------------------------
5A. HTTPS ON APACHE
--------------------------------------------------------------------

Step 5.3  Enable SSL and create the HTTPS virtual host
    a2enmod ssl
    cat > /etc/apache2/sites-available/office-ssl.conf <<'EOF'
    <VirtualHost *:443>
        ServerName office.local
        DocumentRoot /var/www/office
        DirectoryIndex index.html index.php

        SSLEngine on
        SSLCertificateFile    /etc/ssl/office/office.crt
        SSLCertificateKeyFile /etc/ssl/office/office.key
        SSLProtocol -all +TLSv1.2 +TLSv1.3
        SSLCipherSuite HIGH:!aNULL:!MD5:!3DES

        Header always set Strict-Transport-Security "max-age=31536000"

        ErrorLog  ${APACHE_LOG_DIR}/office_ssl_error.log
        CustomLog ${APACHE_LOG_DIR}/office_ssl_access.log combined
    </VirtualHost>
    EOF
    a2ensite office-ssl
    apache2ctl configtest
    systemctl restart apache2




Step 5.4  Test HTTPS in the terminal
    curl -kI https://localhost
    openssl s_client -connect localhost:443 -servername office.local </dev/null 2>/dev/null | grep -E "Protocol|Cipher|subject"

    (-k means "accept the self-signed certificate")




Step 5.5  OPTIONAL - force HTTP to redirect to HTTPS
    Replace the port 80 file with this content:
    cat > /etc/apache2/sites-available/office.conf <<'EOF'
    <VirtualHost *:80>
        ServerName office.local
        Redirect permanent / https://office.local/
    </VirtualHost>
    EOF
    systemctl reload apache2

    WARNING FOR KILLERCODA: The Killercoda browser link (Traffic/Ports) cannot
    resolve "office.local", so the redirect will break your browser test there.
    Do this step LAST, or skip it in Killercoda. On a real server or your own
    VM, add office.local to your PC hosts file and the redirect works well.

5B. TLS FOR POSTFIX AND DOVECOT
--------------------------------------------------------------------

Step 5.6  Dovecot: force encryption (IMAPS 993 / POP3S 995)
    cat >> /etc/dovecot/conf.d/99-office.conf <<'EOF'
    ssl = required
    ssl_cert = </etc/ssl/office/office.crt
    ssl_key  = </etc/ssl/office/office.key

    systemctl restart dovecot

Step 5.7  Postfix: enable STARTTLS on SMTP
    postconf -e "smtpd_tls_cert_file = /etc/ssl/office/office.crt"
    postconf -e "smtpd_tls_key_file  = /etc/ssl/office/office.key"
    postconf -e "smtpd_tls_security_level = may"
    postconf -e "smtp_tls_security_level = may"

    openssl s_client -starttls smtp -connect localhost:25 </dev/null 2>/dev/null | grep -E "Protocol|Cipher"

    Test login over the encrypted IMAP port:
    printf 'a1 LOGIN bob Bob@12345\r\na2 LIST "" "*"\r\na3 LOGOUT\r\n' | openssl s_client -quiet -connect localhost:993 2>/dev/null

    Expected: "a1 OK ... Logged in".

5C. SMALL CRYPTOGRAPHY DEMOS (for understanding)
--------------------------------------------------------------------

Hashing (detect change):
    echo "salary report" > /tmp/file.txt
    sha256sum /tmp/file.txt
    echo "salary report changed" > /tmp/file.txt
    sha256sum /tmp/file.txt
    (A tiny change gives a completely different hash.)

Symmetric encryption (one shared password):
    echo "secret office plan" > /tmp/plan.txt
    openssl enc -aes-256-cbc -pbkdf2 -salt -in /tmp/plan.txt -out /tmp/plan.enc -pass pass:LabPass123
    cat /tmp/plan.enc                (unreadable)
    openssl enc -d -aes-256-cbc -pbkdf2 -in /tmp/plan.enc -pass pass:LabPass123

Asymmetric encryption (public key / private key):
    This is what TLS and SSH use to start a secure session.

PART 6 : SSH KEYS (5.3 SECURE LOGIN)
--------------------------------------------------------------------------------

Step 6.1  Install and start the SSH server
    apt install -y openssh-server
    systemctl enable --now ssh

Step 6.2  Create an admin user for remote login
    useradd -m -s /bin/bash -G sudo sysadmin
    echo 'sysadmin:Sys@12345' | chpasswd

Step 6.3  Generate an SSH key pair (act as the administrator)
    su - sysadmin -c "ssh-keygen -t ed25519 -N '' -f ~/.ssh/id_ed25519"

Step 6.4  Install the PUBLIC key on the server (authorized_keys)
    mkdir -p /home/sysadmin/.ssh
    cat /home/sysadmin/.ssh/id_ed25519.pub >> /home/sysadmin/.ssh/authorized_keys
    chown -R sysadmin:sysadmin /home/sysadmin/.ssh
    chmod 700 /home/sysadmin/.ssh
    chmod 600 /home/sysadmin/.ssh/authorized_keys

    (In a real office you run ssh-keygen on your PC and use ssh-copy-id.)

Step 6.5  Test key login BEFORE you disable passwords
    su - sysadmin -c "ssh -o StrictHostKeyChecking=accept-new -i ~/.ssh/id_ed25519 sysadmin@localhost 'whoami; hostname'"

    Expected: sysadmin  and  mail.office.local

Step 6.6  Harden SSH (only after Step 6.5 worked)
    cat > /etc/ssh/sshd_config.d/99-hardening.conf <<'EOF'
    PermitRootLogin no
    PasswordAuthentication no
    PubkeyAuthentication yes
    PermitEmptyPasswords no
    MaxAuthTries 3
    LoginGraceTime 30
    ClientAliveInterval 300
    ClientAliveCountMax 2
    AllowUsers sysadmin
    EOF
    sshd -t
    systemctl restart ssh

    WARNING: Never close your working terminal until a second login test
    succeeds. A bad SSH config can lock you out of a real server.
    (In Killercoda your terminal is not an SSH session, so you are safe.)

Step 6.7  Prove that passwords are now refused
    ssh -o PreferredAuthentications=password -o PubkeyAuthentication=no alice@localhost

    Expected: "Permission denied" (alice is not allowed, and passwords are off).

PART 7 : FIREWALL (UFW, WITH IPTABLES ALTERNATIVE)
--------------------------------------------------------------------------------

Open ports we need:
    22  SSH          80  HTTP         443 HTTPS
    25  SMTP         993 IMAPS        995 POP3S
Closed on purpose: 3306 (MySQL), 143 (plain IMAP), 110 (plain POP3).

Step 7.1  Install UFW and set default rules
    apt install -y ufw
    ufw default deny incoming
    ufw default allow outgoing

Step 7.2  Allow SSH FIRST (so you do not lock yourself out)
    ufw limit 22/tcp comment 'SSH with rate limit'

Step 7.3  Allow the other services
    ufw allow 80/tcp  comment 'HTTP'
    ufw allow 443/tcp comment 'HTTPS'
    ufw allow 25/tcp  comment 'SMTP'
    ufw allow 993/tcp comment 'IMAPS'
    ufw allow 995/tcp comment 'POP3S'

Step 7.4  Turn it on and view the rules
    ufw --force enable
    ufw status verbose
    ufw status numbered

Step 7.5  Check which services are listening
    ss -tulpn

    MySQL should show 127.0.0.1:3306 only (not 0.0.0.0).

    NOTE: Testing from the same machine (localhost) always bypasses the
    firewall. To truly test, scan from another host or use the Killercoda
    second node if your scenario has one:
        nmap -Pn -p 22,25,80,110,143,443,993,995,3306 SERVER-IP

Step 7.6  Delete or change a rule (practice)
    ufw delete allow 995/tcp
    ufw status numbered

--------------------------------------------------------------------
ALTERNATIVE: IPTABLES (use this instead of UFW, not together)
--------------------------------------------------------------------

    ufw disable
    iptables -F
    iptables -P INPUT DROP
    iptables -P FORWARD DROP
    iptables -P OUTPUT ACCEPT
    iptables -A INPUT -i lo -j ACCEPT
    iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
    iptables -A INPUT -p tcp --dport 22  -j ACCEPT
    iptables -A INPUT -p tcp --dport 80  -j ACCEPT
    iptables -A INPUT -p tcp --dport 443 -j ACCEPT
    iptables -A INPUT -p tcp --dport 25  -j ACCEPT
    iptables -A INPUT -p tcp --dport 993 -j ACCEPT
    iptables -A INPUT -p tcp --dport 995 -j ACCEPT
    iptables -L -n -v --line-numbers

    Save rules after reboot (Ubuntu):
        apt install -y iptables-persistent
        netfilter-persistent save

--------------------------------------------------------------------
ALTERNATIVE: FIREWALLD (Red Hat / CentOS style)
--------------------------------------------------------------------

    firewall-cmd --permanent --add-service={ssh,http,https,smtp,imaps,pop3s}
    firewall-cmd --reload
    firewall-cmd --list-all

PART 8 : ACLs (5.3 ACCESS CONTROL LISTS)
--------------------------------------------------------------------------------

Scenario: A shared folder /srv/office-docs.
    Group "finance" : full access
    Group "hr"      : read only
    User  "bob"     : read only (he is IT, needs to check files)
    Everyone else   : no access

Step 8.1  Create groups and folder
    groupadd finance
    groupadd hr
    usermod -aG finance alice
    usermod -aG hr bob
    mkdir -p /srv/office-docs
    chmod 770 /srv/office-docs

Step 8.2  Set ACLs
    setfacl -m g:finance:rwx /srv/office-docs
    setfacl -m g:hr:r-x      /srv/office-docs
    setfacl -m u:bob:r-x     /srv/office-docs

Step 8.3  Default ACL (new files inherit the same rules)
    setfacl -d -m g:finance:rwx /srv/office-docs
    setfacl -d -m g:hr:r-x      /srv/office-docs

Step 8.4  View the ACL
    getfacl /srv/office-docs
    ls -ld /srv/office-docs         (a "+" at the end means an ACL exists)

Step 8.5  Test the permissions
    su - alice -c "touch /srv/office-docs/budget.txt && echo alice can write"
    su - bob   -c "touch /srv/office-docs/test.txt"
    su - bob   -c "ls /srv/office-docs"

    Expected: alice can write; bob gets "Permission denied" on touch,
    but bob can list files.

Step 8.6  Remove an ACL
    setfacl -x u:bob /srv/office-docs
    setfacl -b /srv/office-docs        (removes ALL ACL entries)

Other ACLs used in this project:
    Apache   : "Require ip" and "Require valid-user" in office-dirs.conf
    Postfix  : "mynetworks" and "smtpd_*_restrictions"
    Firewall : UFW / iptables allow and deny rules
    MySQL    : GRANT / REVOKE for each database user

PART 12 : SHORT VIVA QUESTIONS
--------------------------------------------------------------------------------

Q1. What is the difference between SMTP and IMAP?
    SMTP sends mail between servers. IMAP lets a user read mail on the server.

Q2. Why is the DB config file kept outside /var/www/office?
    So the web server can never show it as plain text if PHP breaks.

Q3. Why use SSH keys instead of passwords?
    Keys cannot be guessed by brute force and the private key never leaves
    your computer.

Q4. Why allow SSH in the firewall before enabling it?
    Otherwise the firewall blocks your own connection and you lock yourself out.

Q5. What is an open relay?
    A mail server that sends mail for anyone. Spammers abuse it. We prevent it
    with reject_unauth_destination and mynetworks.

Q6. Self-signed vs CA-signed certificate?
    Both encrypt. Only a CA-signed one is trusted by browsers automatically.

Q7. What does a "+" at the end of ls -l permissions mean?
    The file has an ACL.
